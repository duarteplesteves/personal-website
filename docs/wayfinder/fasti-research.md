# fasti: public evidence

Research for [#89](https://github.com/duarteplesteves/personal-website/issues/89), checked 26 November 2026.

## What ships

- **Release baseline:** npm [`@fastijs/scheduler` 0.8.2](https://registry.npmjs.org/@fastijs%2Fscheduler/0.8.2) is the `latest` dist-tag and matches the [latest non-prerelease GitHub release](https://github.com/duarteplesteves/fasti/releases/tag/v0.8.2). The npm `gitHead`, `v0.8.2` tag and `main` all pointed to `8e2d53b282713d8e9a7a95c6d587dcb07993bfdd`; no main-only functionality to distinguish at this snapshot. It's a published 0.x release, not a frozen 1.0 API. The [roadmap](https://github.com/duarteplesteves/fasti/blob/v0.8.2/ROADMAP.md) lists the API freeze and a docs site as future work.
- **Audience and scope:** MIT-licensed TypeScript library for developers adding scheduling to their own backend and database. The scheduler handles one bookable resource per booking (such as a person or room): find slots, book, reschedule, cancel and configure booking status transitions. Opt-in plugins add weekly opening hours (with date exceptions) and one-off blocks; notice and app-defined policies, hooks and custom plugins extend the workflow. The separate stateless `/core` entry point calculates slots, expands rules and checks conflicts with data supplied by the caller, without a database or runtime dependencies. [README](https://github.com/duarteplesteves/fasti/blob/v0.8.2/README.md) · [Actions](https://github.com/duarteplesteves/fasti/blob/v0.8.2/docs/guides/actions.md) · [Core](https://github.com/duarteplesteves/fasti/blob/v0.8.2/docs/guides/core.md)
- **Getting started:** `npm install @fastijs/scheduler` (or `bun add @fastijs/scheduler`). Requires native `Temporal`: Node.js 26+ or Bun 1.4+ are documented. Use the README's in-memory example to try it without a database, or define a schema, migrate your own tables and pass an adapter to `createScheduler`. Actions are available as plain async calls or via the [Effect service](https://github.com/duarteplesteves/fasti/blob/v0.8.2/docs/guides/effect.md). The package also ships guides and a [coding-agent skill](https://github.com/duarteplesteves/fasti/releases/tag/v0.8.2).
- **Adapters:** Drizzle on PostgreSQL (`drizzle-orm` 1.0 RC.5+); Drizzle on libsql SQLite (file databases, one writer process, no overlap backstop); Prisma 8 on PostgreSQL (experimental); memory (non-persistent, for tests/prototypes). Developers can write an adapter and use the published conformance suite. [Database guide](https://github.com/duarteplesteves/fasti/blob/v0.8.2/docs/guides/databases.md) · [Custom adapters](https://github.com/duarteplesteves/fasti/blob/v0.8.2/docs/guides/custom-adapter.md)

## What the types do (and don't do)

- The schema drives required/optional booking fields, resource ID types (including brands), allowed status transitions and which plugin methods are exposed. Applicable policy names and expected action failures are typed; plain async uses a discriminated `Result`, Effect a tagged error channel. [Schema guide](https://github.com/duarteplesteves/fasti/blob/v0.8.2/docs/guides/schema.md) · [API type tests](https://github.com/duarteplesteves/fasti/blob/v0.8.2/src/framework/types.test.ts) · [Plugin type tests](https://github.com/duarteplesteves/fasti/blob/v0.8.2/src/framework/plugin.types.test.ts)
- Static types don't establish availability, authorise exceptions or prevent races. Runtime checks and adapter transactions enforce overlap rules on scheduler writes; slots shown by a search aren't reservations. On PostgreSQL, the optional `EXCLUDE` constraint must be migrated separately to prevent overlapping blocking bookings from writes outside fasti. The host app owns access control. [Policies and invariants](https://github.com/duarteplesteves/fasti/blob/v0.8.2/docs/adr/014-invariants-and-relaxable-policies.md#amendment-2026-11-23-plugins-feed-the-overlap-invariant-and-bring-policies) · [Database backstop](https://github.com/duarteplesteves/fasti/blob/v0.8.2/docs/guides/databases.md#the-backstop)
- No hosted service, UI, built-in email/payments/calendar sync, booking list/get action, recurring booking series, shared capacity or atomic multi-resource booking in this release. Weekly availability is not recurring bookings. [README](https://github.com/duarteplesteves/fasti/blob/v0.8.2/README.md) · [Roadmap](https://github.com/duarteplesteves/fasti/blob/v0.8.2/ROADMAP.md#beyond-the-framework)

## Possible story evidence (not editorial decisions)

- **Exceptions without overlaps:** the [PostgreSQL example](https://github.com/duarteplesteves/fasti/blob/v0.8.2/examples/basic/plain.ts#L126-L152) records a past walk-in by waiving minimum notice and keeps the waiver visible in the result. That exception can't override an overlap. The [custom holiday plugin example](https://github.com/duarteplesteves/fasti/blob/v0.8.2/examples/basic/plain.ts#L311-L353) makes the same distinction: holiday busy time can't be waived; a holiday-eve rule can. Neither is a bundled walk-in workflow or holiday feed.
- **One transaction for booking and app data:** the [prepaid-credit example](https://github.com/duarteplesteves/fasti/blob/v0.8.2/examples/basic/plain.ts#L224-L266) debits a credit in the caller's table via `also`, or vetoes and rolls back the booking when the pack is empty. [ADR 015](https://github.com/duarteplesteves/fasti/blob/v0.8.2/docs/adr/015-developer-writes-inside-the-action-transaction.md) explains why a per-resource lock alone can't enforce a limit shared across resources. This is example app logic, not bundled billing.
- **Wall-clock predictability versus coverage:** during a DST change, slot generation skips missing local times and emits only the first occurrence of a repeated time. [ADR 005](https://github.com/duarteplesteves/fasti/blob/v0.8.2/docs/adr/005-dst-policy.md) records the trade-off: no duplicate local slot labels at the cost of not listing the second occurrence.

**Verification limits:** Installed npm 0.8.2 and ran the README memory example on Node.js 26.13.0 and Bun 1.4.4 (16 free slots, a successful booking, and `SlotConflict` for an overlapping one). [Public CI for the matching commit](https://github.com/duarteplesteves/fasti/actions/runs/45801888581) passed type checks, tests and the PostgreSQL examples. Database integrations weren't independently re-run; production adoption and performance weren't verified.
